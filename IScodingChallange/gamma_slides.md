# 2. 문제 정의 (Why ECO-Cargo AI?)

### 전남 물류/에너지 분야를 선택한 이유
- 전남은 여수·광양 국가산업단지, 목포항, 대불산단 등 물류·에너지 중심 산업이 밀집한 지역
- 장거리 화물 운송이 많아 유류비가 사업자의 핵심 원가 구조를 차지
- 고령화된 화물차 기사 비중이 높아, 디지털 접근성이 낮은 사용자를 위한 서비스 설계가 필요

### 페르소나: 정기철 기사 (50세)
| 고충 | 상세 내용 |
|---|---|
| 에너지 비용 민감성 | 리터당 10~20원 차이도 월 수십만 원 차이로 이어짐 |
| 장거리 운행 피로 | 야간·장거리 운행이 잦아 집중력 저하, 안전사고 위험 증가 |
| 분산된 정보 | 유가는 오피넷, 휴게소는 도로공사, 날씨는 기상청 앱을 따로 확인해야 함 |

**대본:**
"정기철 기사님은 매일 여수에서 나주까지, 혹은 그 이상 장거리를 운행합니다. 문제는 유가 정보,
휴게소 정보, 날씨 정보가 모두 다른 앱에 흩어져 있다는 것입니다. 운전 중에 여러 앱을 오가는 것은
피로와 사고 위험을 동시에 높입니다. 저희는 이 세 가지 정보를 하나의 화면에, 그것도 화물차에
최적화된 형태로 통합하고자 했습니다."

# 4. 기술 스택 및 시스템 구성

### 기술 스택
- **언어:** Python 3.11
- **프레임워크:** Streamlit
- **지도 시각화:** Folium, streamlit-folium
- **데이터 처리:** pandas
- **공공 API:**
  - 오피넷(OPINET) — 실시간 유가 정보
  - 한국도로공사(EX) — 휴게소·교통 정보
  - 기상청(KMA) — 실시간 기상 정보

### 시스템 아키텍처 흐름
```mermaid
flowchart LR
    A[사용자 입력: 출발지/도착지/음성] --> B[공공 API 호출]
    B -->|응답 성공| C[실시간 데이터 정규화]
    B -->|0.1초 초과/오류| D[로컬 Fallback 데이터]
    C --> E[통합 데이터 모델]
    D --> E
    E --> F[HUD 대시보드 렌더링]
    F --> G[지도 시각화 + 절감액 계산 + 음성 브리핑]
```

**대본:**
"저희는 Python과 Streamlit을 기반으로 빠르게 프로토타입을 구현했고, 공공 API 응답이 0.1초를
초과하거나 오류가 발생하면 즉시 로컬 데이터로 전환하는 Fallback 아키텍처를 적용해 서비스 신뢰성을
확보했습니다."

# 5. 핵심 기능 시연 (1) — 데이터 흐름

# 7. 바이브 코딩 활용 내용 (1) — Fallback 로직 구현

### GitHub Copilot과의 실제 대화

**프롬프트:**
```
공공 API가 응답 지연되거나 장애가 났을 때, 0.1초 안에 무조건
로컬 하드코딩 데이터로 전환되는 Fallback 로직을 짜줘.
requests 타임아웃 기준으로 구현하고, 실패 사유와 전환 시간을
화면에 표시해줘.
```

**Copilot 응답 요약:**
- `requests.get(..., timeout=0.1)` 하드 타임아웃 적용
- `try-except Exception`으로 Timeout, ConnectionError, JSON 파싱 오류까지 포괄 처리
- `time.time()`으로 전환 소요 시간을 측정해 `"FALLBACK (32ms 내 로컬 데이터 전환)"` 형태로 실시간 표시

**대본:**
"Fallback 로직은 서비스 신뢰성의 핵심입니다. Copilot에게 정확한 타임아웃 수치와 예외 처리 범위를
명시해서 요청한 결과, 단 몇 번의 대화만으로 실제 코드에 바로 적용 가능한 견고한 예외 처리 로직을
완성할 수 있었습니다."

# 11. 기술성 증명 — Fallback 0.1초 전환 기술

### Fallback 아키텍처의 우수성
- 모든 공공 API 호출에 **0.1초(100ms) 하드 타임아웃**을 설정하여, 응답 지연 시 즉시 로컬 데이터로 전환
- `try-except Exception` 광범위 처리로 Timeout, ConnectionError, JSON 파싱 오류 등 모든 장애 유형에 대응
- 전환 소요 시간을 실시간 측정(`time.time()`)해 화면에 투명하게 표시 → 사용자 신뢰도 확보
- API 키 미설정 상태에서도 즉시 Fallback이 동작해, 네트워크 환경과 무관하게 서비스 연속성 보장

### 기술적 의의
운전 중인 화물차 기사에게 "로딩 중" 화면이나 서비스 중단은 곧 안전 위협으로 이어질 수 있습니다.
ECO-Cargo AI는 이를 원천 차단하는 구조로 설계되었습니다.

**대본:**
"화물차는 잠시도 멈출 수 없습니다. 저희 Fallback 기술은 API 장애 시에도 0.1초 안에 서비스가
끊김 없이 이어지도록 보장하여, 실제 현장에서 사용 가능한 신뢰성을 확보했습니다."

# 12. 확장성 — 호남권 지자체 물류 데이터 연계 방안

### 확장 로드맵
1. **1단계 (현재):** 전남 지역 오피넷·도로공사·기상청 공공 API 연동 프로토타입
2. **2단계:** 광주·전북 등 호남권 전역의 지자체 물류 데이터(산단 입출차 정보, 지역 화물 수요 데이터) 연계
3. **3단계:** 지자체 스마트물류센터, 항만공사(광양항·목포항) 실시간 물동량 데이터와 연동한 광역 물류 최적화
4. **4단계:** 호남권 화물차 공동배차 플랫폼으로 고도화, 지역 중소 물류사업자의 공차율 감소 지원

**대본:**
"ECO-Cargo AI는 전남에서 시작하지만, 호남권 전체 지자체의 물류 데이터와 연계될 경우 광역
물류 최적화 플랫폼으로 확장될 잠재력을 가지고 있습니다. 이상으로 발표를 마치겠습니다.
감사합니다."
